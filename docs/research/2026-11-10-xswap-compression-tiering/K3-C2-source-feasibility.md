# K3: C2 source feasibility review

Status: conditionally ready for C2 implementation with the coordinator-accepted requirements below. No implemented-patch approval, capability activation or runtime admission.

Pinned interface K: `7d5a3cfab2abb37b33afc03ed365d3024bd3d5ad`, tree `8b085adc109e3b5467c3de998f11b04517f052a5`. Native comparison/parent A remains `5e84ca928deeacb4eee656806a003f27d1eca82f`. The C1 canonical correctness manifest records the completed matrix; C1 timing is a separate unresolved observer failure.

This review owns only this document. It examines the chosen callback, cap, accounting, diagnostic and test design against K. No kernel source, trusted adapter, protocol, ledger, build, guest, host state or publication was changed or launched.

## Decision

The synchronous frontend is feasible in the approved files. The coordinator selected one nonblocking per-device store token, and accepted a bounded debug preparation path for the old-physical-copy test. The current wire is not yet sufficient: it needs retained-folio preparation, exact completion lifetime, and a distinction between observed pool-counter peak and the source-derived transient allocation bound. These are pre-freeze implementation requirements, not runtime passes.

Confidence is high for the pinned call/lock constraints, medium for the proposed implementations. Exact candidate review and all counted tests can change this disposition.

## Store token, cap and finite headroom

The library's per-CPU context mutex covers one base-page operation, not all unpublished handles (`mm/page_compress.c:257-305`). The coordinator-selected frontend token spans the whole folio store, per-subpage allocation/cap check/publication, and rollback. Acquire without waiting; contention returns RETRY with the input locked and authoritative. Never wait for this token during recursive reclaim. This deliberately serializes stores per device and can reduce write-side concurrency; measurement must retain that cost.

Let C be the current cap and M=`CONFIG_ZSMALLOC_CHAIN_SIZE`. K bounds M to 4..16 (`mm/zsmalloc.c:118-132`); a new allocation constructs at most one M-page chain (`:1020-1060,1308-1353`). Before every subpage allocation, read actual backing pages B. If cap=0, or B>=C, refuse new admission. After a successful library allocation, sample B again before publication; if B>C, free that unpublished handle and roll back the entire rewritten folio. Initialize/charge each entry before index publication. Recheck cap under the same token; cap updates serialize with it in process context. The input folio lock protects the range across all subpages.

With one allocating store and no other frontend pool allocator, a store adds at most M uncommitted backing pages beyond the preceding sample. Thus the registered backing-page count during newly admitted work is bounded conservatively by C+M, independently of CPU count and folio order (the strict integer precheck gives C+M-1 when C is fixed and positive). Each subpage is checked; do not allocate a whole folio before one final check. `folio_alloc_swap()` already limits a folio to one swap cluster (`mm/swapfile.c:2126-2141`). Metadata, codec contexts, handles, charges and physical staging are separate costs.

`zs_free()` can leave an empty chain pending asynchronous free (`mm/zsmalloc.c:1450-1484,1873-1913`). If rollback leaves B>C, the next store must refuse before allocating; otherwise repeated failures can accumulate transient chains. Lowering C below existing B also blocks new allocation until B falls. For a cap-lowering interval beginning with B0, the conservative bound is max(B0,C+M); preexisting B0 is retained residency, not new cap-compliant admission. Deferred chains remain counted until their actual free path completes (`mm/zsmalloc.c:890-918,1480-1482,1893-1901`), so they cannot create unbounded hidden admission headroom. No eviction occurs.

The API returns the allocator's atomic registered-chain count (`mm/page_compress.c:378-380`, `mm/zsmalloc.c:1119-1122`). Sample its peak immediately after each successful allocation and before every free, including rejected allocations. A partly built chain that fails inside `zs_malloc()` is freed before the API returns and never enters that counter. Therefore the observed peak is a registered-pool-counter peak; C+M is a source-derived bound on store allocation headroom. Neither is an exact instantaneous total-RAM peak: core page migration can temporarily hold old/new physical pages without changing this pool counter (`mm/zsmalloc.c:1752-1854`), and allocator metadata and the partly constructed chain are outside it. The wire/report must name this distinction; an exact physical-allocation high-water measurement would need extra allocator instrumentation outside this review's chosen implementation.

## Ownership and lock order

Use the locked swap-cache folio and existing device lifetime as C2's first owner model; do not add an extra per-object wrapper merely for abstraction. K explicitly excludes concurrent same-key stores/invalidation with the folio lock (`mm/zswap.c:1307-1315,1470-1473`). `swap_range_free()` runs before the slot-release barrier (`mm/swapfile.c:1644-1670`) and may be under the cluster lock (`:2332-2381`). A load keeps its folio locked across lookup, decode, dirty/uptodate publication and compressed retirement. A store initializes handle, charge and owner before index/LRU exposure. A terminal decode error retains the compressed source.

Use one frontend index lock for the index and intrusive LRU, or explicitly order them. The permitted nesting is logical cluster -> frontend index/LRU; physical-cluster nesting already follows logical cluster (`mm/swapfile.c:3349-3375`). No frontend index/LRU lock may surround a cluster lookup, compression, generic charge, mutex wait or pool destruction. A whole-range compressed query under cluster lock takes only the non-sleeping frontend lock and copies scalar presence. Observer walks copy scalars while protected; no pointer escapes unpinned.

Final invalidation erases index/LRU reachability synchronously before the slot can be reused. `page_compress_free()` delegates to non-sleeping `zs_free()`; generic uncharge delegates to stock refill, and objcg put uses percpu reference release (`mm/page_compress.c:373-375`, `mm/memcontrol.c:3516-3590,3645-3647`, `include/linux/memcontrol.h:812-815`). The last-owner path can therefore release handles/charges without a new retirement work queue. If an implementation introduces a reader that escapes the folio/device protection, it must add a real pin and re-review final release; RCU alone is insufficient.

Keep frontend operations available through successful `try_to_unuse()`. K then kills device users, waits RCU/completion and flushes work before teardown (`mm/swapfile.c:4104-4152`). Debug control references must be cancelled/drained before that wait, not held by a control operation waiting for swapoff to finish. Snapshot reads copy into independent buffers. A retained terminal record is copied only after `page_compress_destroy()` returns. After users, debug references and handles have drained, take the last live pool sample through a bounded process-context poll. The required pre-destroy observation is zero. On a poll timeout, preserve the actual nonzero value and fail that teardown-evidence gate; actual destruction can still run its normal deferred-free flush (`mm/zsmalloc.c:2251-2257`). There is no public separate flush API. Do not reinsert a device after its users have been killed, read the pool after destruction, or fabricate zero from a returned destructor.

## Real BIO completion injection

Bind the target at actual physical submission to a scalar request record: logical type/generation/key/range, physical type/key/range, direction and token. The `swap_iocb` batches physical entries and can include multiple folios (`mm/page_io.c:355-392`); its first entry alone cannot certify every logical owner. Use a preallocated debug record attached to the selected request or embedded diagnostic slot; no allocation/sleep in completion. Refuse ambiguous mixed matches instead of changing normal merge behavior just for the test.

At `end_swap_bio_write()` or `swap_bio_read_end_io()`, record the real original status before once-only injected status is substituted (`mm/page_io.c:582-637`). Then run the existing completion owner. Observe write redirty/reclaim-clear before `folio_end_writeback()`, and read not-uptodate before `folio_unlock()` (`:547-614`). The final action can release the last folio/descriptor protection: record its invocation and immutable scalars, then emit post-action completion from the retained scalar record. Do not dereference the folio or sio after end/unlock/free without an additional explicit reference. Debug record references must drain before frontend teardown. No completion callback waits at a diagnostic barrier. Preserve actual diagnostic checks and distinguish expected typed injection from a real device error.

## Retained old physical copy: approved debug preparation

Ordinary physical-store/read/modify/store is insufficient. XSwap sets SWP_SYNCHRONOUS_IO (`mm/swapfile.c:5512`); demand read tries `folio_free_swap()` even for read faults (`mm/memory.c:4686-4687,5266-5267`). Exclusive order-zero traffic releases the old key, while a fork may force COW. Matching numerical offsets after reuse is not same-ownership evidence.

The coordinator accepted this narrowly coordinated debug setup:

1. Arm one generation/key/range-matched retain operation. At the real physical fallback, after pageout eligibility and immediately before `__swap_writeout()`, take one extra reference to the actual swap-cache folio. The eligibility check precedes `swap_writeout()` (`mm/vmscan.c:715-732`); taking a reference earlier would prevent the intended pageout.
2. Let actual physical I/O run. Record a successful original and final BIO completion for V0. The extra reference keeps the cache folio alive; it creates no association or completion. Observe the real logical/physical mapping.
3. A process-context rewrite command waits writeback, locks the retained folio, and revalidates device generation, exact `folio->swap`, swap-cache membership, uptodate state, no live user mappings and positive real swap count. Any mismatch is INCOMPLETE and releases the retained ownership. Do not add a fake swap count.
4. With admission restored, overwrite the still-owned input with the declared deterministic V1 pattern, mark/clear dirty through the real writeout preparation, and call actual `swap_writeout()`; flush any real pending I/O context on error. Check the declared return/lock ownership. Require real compressed publication and zero second physical-write delta; otherwise the preparation fails.
5. Release the extra reference, let normal reclaim evict swap cache, and verify swapped/nonresident same key and data generation. Then perform the real decode-failure demand fault. Require SIGBUS/no old-physical read and preserved compressed source until cleanup.

Minimal new wire operations are `retain_write ...`, `rewrite_retained ... pattern_generation=V`, and `release_retained ...`, all bound to one control open, token and generation/key. Arm/capture occurs once; stale/multiple matches fail. Closing the file, timeout, cancellation or teardown disarms and drops the reference exactly once through safe process-context cleanup. An abandoned retained reference cannot block swapoff indefinitely. Keep captured/completed/rewritten/released states and exact data-generation observations distinct. This is a coordinated debug preparation, not a naturally observed overwrite workload; no PTE/xs_table or counter mutation is allowed.

## Race and high-order evidence

Hold after load lookup only with the folio/device protected and no index/cluster/LRU spinlock held. A peer's real swapoff/unuse can enter and wait for that folio (`mm/swapfile.c:3539-3555`); log exact entry, hold interval and eventual result. Actual same-key detach/reuse cannot occur while the load owns the locked swap-cache folio. Therefore an entry-and-wait overlap is valid only under the wire's explicit blocked-operation rule; label it as such. Do not synthesize a detach during the hold. Slot reuse requires observed prior retirement, later actual allocation and a new data generation, never pathname/offset equality alone.

`destroy_before_unuse` can be placed after preliminary XSwap map/shrink waits and before `try_to_unuse()` with no spinlock held (`mm/swapfile.c:4095-4108`). `backing_swapoff_enter` must snapshot the real reverse mapping, release the physical cluster lock, pin its owner and only then hold (`:3494-3526`). Revalidate the mapping after release because real concurrent release is permitted. Never hold a physical cluster lock while acquiring the logical cluster or sleeping.

Legacy pool/offline events must observe actual legacy code. Pool release is a sleepable RCU-work function (`mm/zswap.c:336-346`); memcg offline reaches `zswap_memcg_offline_cleanup()` before generic objcg reparenting (`mm/memcontrol.c:4458-4482`). Emit entry/exit around those actual functions; any hold in offline must precede its spinlock (`mm/zswap.c:655-664`). Bind the selected ordinary-device epoch, held owner identity and old pool identity. A stopped worker or two started threads is not proof these intervals overlap. No new XSwap offline policy is needed.

Real higher-order stores are reachable without changing vmscan: THP swap allocation permits up to a cluster and normal reclaim calls `swap_writeout()` on the actual folio (`mm/swapfile.c:2126-2141`, `mm/vmscan.c:1373-1407,1438-1466`). A guest must create/fill a real large anonymous folio, verify its actual input order at the frontend, and fail INCOMPLETE if splitting occurs. Target first/middle/last failures from the observed order. Do not let requested THP size or a synthesized event establish coverage.

## Wire and cleanup refinements for H24

The coordinator accepted the retained-folio preparation, two-drain distinction, registered-counter bound, scalar completion-owner transitions and separate real ordinary-device overlap. H24 owns the final exact field/response grammar. The minimal retained-folio operations are:

    retain_write type=T generation=G token=U key=K count=1 timeout_ms=D
    rewrite_retained type=T generation=G token=U key=K pattern_generation=V timeout_ms=D
    release_retained type=T generation=G token=U key=K

`retain_write` is an arm operation within an existing targeted window. It cannot certify a physical store. Resolve `key=next` only at the actual one-shot capture, then echo the concrete logical key, order/range and real physical association. `rewrite_retained` must use that concrete key. One open owns one record; no second capture/retain command can overwrite a live or unacknowledged record. A fixed finite D is frozen by the trusted capability, not chosen arbitrarily by the guest. The retained states are armed, captured, physical_completed, rewrite_running, compressed_published, released, or cancelled/failed. They are observed transitions, not guest assertions.

Use the retained record's own lock/refcount to transfer reference ownership once. At capture, take the folio reference under the existing lock; never add a swap-count reference. At rewrite start, move/claim that reference for the command so a concurrent close/cancel cannot put it underneath the command. Wait for actual writeback completion and acquire the folio lock through deadline/cancellation-aware process-context logic. Do not hold the control-record lock, frontend index lock, cluster lock or store token while waiting. Revalidate swap-cache membership, exact range, generation, uptodate, unmapped state and a positive actual `swp_swapcount()` before changing data (`mm/swapfile.c:2421-2444,2447-2484`). The ordinary owner process stays alive and does not touch/unmap the target during preparation; otherwise swap counts may decrease concurrently and the preparation must fail its identity/effect checks. Positive counts are a real observation, not an invented pin.

The rewrite creates a fresh local `swap_io_ctx`, marks and clears dirty through the same preparation as pageout, then invokes the real `swap_writeout()`. AOP_WRITEPAGE_ACTIVATE keeps the lock; success/negative error unlock according to the reviewed page-IO path. Flush a real pending context through the normal submit helper on every exit that owns one. After a successful RAM result, clear stale reclaim bookkeeping as the real pageout caller does (`mm/vmscan.c:719-743`); do not fabricate writeback for compressed storage. Require actual V1 publication, exact V0 association still present and zero second physical-write delta. A fallback or identity change is a failed preparation, even if data remains recoverable. V1 is written only in this explicit debug fixture, never in ordinary operations.

Close, cancellation and timeout first disarm future capture, release held barriers, and atomically claim any idle retained reference for exactly one process-context put. An active rewrite retains its own reference until it observes cancellation or its normal call returns; cleanup cannot force-unlock its folio, end its writeback or declare it completed. A timer may mark cancellation and schedule cleanup, but cannot wait in timer/completion context. Before swapoff starts unuse, cancel diagnostics and boundedly drain any command/retained owner that pins the device. If that diagnostic drain cannot finish while the device is still recoverable, abort through the existing reinsertion/error path with the frontend intact. The later `percpu_ref_kill()`/completion wait must not depend on a control owner waiting for swapoff itself. This is separate from the post-user allocator poll above. A hung real codec/I/O path remains a counted runtime timeout, not a synthesized cancellation success.

BIO completion records distinguish three stages: original completion status; injected status before the real branch; and actual completion-owner return. Sample dirty/reclaim or not-uptodate before the final folio action. Copy immutable identities and action evidence before `folio_end_writeback()`/`folio_unlock()` and `mempool_free()`; emit the post-owner record only from the retained scalar record. A post-owner record must not claim a fresh folio flag sample from stale pre-owner bits. Injection that cannot bind every affected bvec to the prescribed generation/range remains incomplete; ordinary merge rules stay unchanged. This diagnostic fits `include/linux/swap_ops.h`, `mm/page_io.c`, new private XSwap state and the approved declarations.

Define `peak_backing_pages` as the maximum observed registered-pool-counter sample, including post-allocation samples before rejected handles are freed. Source review/final configuration supply M. A fixed-cap bound check may compare against C+M; a later lower cap must preserve B0 and cannot reinterpret an earlier peak as a breach of the new cap. Exact total-RAM peak remains outside this contract.

## Exact legacy overlap and scope findings

A real old-pool release cannot enter while a live entry still holds that same pool: `__zswap_pool_empty()` queues release only after the reference reaches zero (`mm/zswap.c:349-360`), and the worker asserts zero before destruction (`:336-346`). Do not require or claim old-pool destruction concurrent with mutation of a live object from that pool. A feasible legacy pool/offline case switches to a new pool, retires the selected old-pool entries, holds the real release worker at entry, then enters the real selected owner's `zswap_memcg_offline_cleanup()` before its spinlock. Keep separately observed current-pool ordinary objects and XSwap objects resident if the phase requires both frontends live. Bind the overlap to the actual ordinary-device epoch, owner inode, selected old-pool lifetime and test token; bare reusable pool index or pointer equality after reuse is insufficient. Copy the worker's identity before destruction and emit exit from safe scalar state. Neither hook needs a new independent-XSwap memcg-offline policy.

For same-key races, folio locking excludes simultaneous mutation. A load can hold after lookup while real unuse/destroy or a fault enters a reviewed wait stage. The peer interval includes its exact kernel entry/wait location and eventual result. Physical-backing swapoff takes its owner reference only after dropping the physical cluster lock and revalidates the logical association afterward (`mm/swapfile.c:3494-3526`); sleeping with that cluster lock or acquiring the logical cluster underneath it is forbidden. Reuse is a later actual allocation with a new data generation after retirement, never forced reuse while the locked old folio owns the key.

The complete requirement is source-feasible within the stated allowlist: per-device state/cap/test records in new `mm/xswap.c` and `mm/xswap.h`; existing page-IO and swapfile callback/teardown hooks; private `swap_iocb` diagnostic state; legacy observation in already-carried `mm/zswap.c`; and existing approved Kconfig/header/accounting integration. No zsmalloc, vmscan, public cgroup ABI, PTE or xs_table test mutation is needed. Genuine large-folio coverage remains conditional on the guest creating a real folio that reaches the frontend at order>0; source reachability is established, 900-second execution feasibility is not. These additional diagnostic requirements have not been implemented or measured against the cumulative file/line budget.

## Focused candidate source-review checklist

- Review both A-to-C cumulative changes and K-to-C frontend changes; keep every test/debug operation in its allowed configuration and verify disabled configurations use correct stubs.
- Trace every store/load result through page-IO to the existing callers: locked return, one caller unlock, no RAM writeback fabrication, terminal decode preservation, physical fallback and no unrelated batch flush.
- Prove one whole-folio nonblocking store token, pre/post checks for every subpage, immutable initialized/charged publication, complete partial rollback, deferred-free admission blocking and cap-change serialization.
- Trace handle, entry, objcg and device ownership through success, failure, invalidate and teardown. Confirm non-sleeping erase/free/uncharge under cluster context; no escaping object pointer or unpinned snapshot reader.
- Inspect lock ordering for index/LRU, logical cluster, physical cluster, folio, diagnostic record and process-context waits. Every hold/rewrite path must release spinlocks before sleeping and must have a finite cancellation route.
- Verify retained-folio V0/V1 preparation uses actual I/O/publication and positive real swap ownership, transfers its one reference safely, and cancels/drains before device-user destruction. Ordinary fault/rewrite cannot substitute for this fixture.
- Follow every selected BIO bvec from logical/physical submit identity to real completion owner; original/injected statuses and pre-action state are explicit, post-owner records contain safe scalar evidence only.
- Verify actual old-pool/offline and same-key entry/wait intervals, real higher-order input and actual NUMA backing pages. Requested barriers/order/nodes cannot populate observed-success fields.
- Inspect terminal accounting after all users/handles drain: actual pre-destroy zero sample or explicit timeout failure, real destructor return, no post-free reads, no fabricated reset and no unbounded diagnostic reference.

## Limits and readiness

Only source inspection and this document were performed. No C2 code, compilation, runtime, timing, bug reproduction, core change or publication occurred. This is a design feasibility review, not an implemented-patch approval. The coordinator owns the accepted store-token and retained-folio choices; H24 owns exact wire/adapters. No unresolved source-level feasibility blocker remains within this assigned design scope. H24 must encode these accepted recipes in the exact wire/adapters, and the kernel worker must implement them within the frozen allowlist and limits. This is conditional readiness for implementation. Real higher-order/NUMA placement, bounded drain and grouped runtime duration remain unmeasured; the full candidate still requires independent source review and all native C2 gates before runtime/capability acceptance.
